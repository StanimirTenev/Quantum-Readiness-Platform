# Graph Snapshot Loader Design

**Status:** Graph Snapshot Loader Design — docs-only, not implemented.

## 1. Purpose

This document defines a future read-only Graph Snapshot Loader for generated graph snapshot JSON.

This document is design-only and does not implement the loader.

## 2. Current state

- graph snapshot is generated by existing projection tooling
- graph API contract tests exist
- graph API is not implemented
- loader runtime is not implemented
- graph remains JSON Snapshot First
- no graph DB/Neo4j exists

## 3. Non-goals

- no loader implementation
- no graph API implementation
- no route/endpoint implementation
- no graph DB
- no Neo4j
- no graph UI
- no traversal engine
- no blast-radius engine
- no snapshot mutation
- no LLM graph reasoning

## 4. Loader principles

- read-only
- deterministic
- local file only
- no network access
- fail safely
- schema-version aware
- no mutation of snapshot file
- no dependency on graph DB
- no dependency on live inventory/risk/planner calls

## 5. Proposed loader responsibilities

Future loader responsibilities are limited to:

- locate configured snapshot path
- read JSON snapshot
- validate required top-level keys
- validate supported graph_schema_version
- validate node ids
- validate edge references
- expose normalized in-memory read model
- return structured errors for missing/invalid snapshot

## 6. Explicit non-responsibilities

The future loader should not:

- generate snapshots
- modify snapshots
- query live services
- execute graph traversal
- calculate blast radius
- infer relationships with LLM
- redact data dynamically beyond what snapshot already provides
- export to external systems

## 7. Configuration design

Future configuration is conceptual only:

- `GRAPH_SNAPSHOT_PATH` optional
- default path `reports/graph/latest/graph-snapshot.json`
- allowed local relative or absolute path
- reject remote URLs
- fail closed on missing/invalid path

No configuration is implemented now.

## 8. Error model

Future structured error identifiers:

- `graph_snapshot_missing`
- `graph_snapshot_invalid_json`
- `graph_snapshot_unsupported_schema_version`
- `graph_snapshot_missing_required_keys`
- `graph_snapshot_duplicate_node_id`
- `graph_snapshot_invalid_edge_reference`
- `graph_snapshot_unsafe_path`

## 9. In-memory read model

Conceptual, future in-memory read model types:

- `GraphSnapshot`
- `GraphNode`
- `GraphEdge`
- `GraphWarning`
- `GraphSummary`

This model description is conceptual only.

## 10. Compatibility with future Graph API

A future read-only Graph API could consume the loader for these conceptual endpoints:

- `/graph/snapshot`
- `/graph/summary`
- `/graph/nodes`
- `/graph/edges`
- `/graph/warnings`

These endpoints are design references only and are not implemented.

## 11. Validation approach

Future phases:

- Phase 0 — docs-only design
- Phase 1 — loader contract tests against static snapshot
- Phase 2 — loader helper implementation, no API
- Phase 3 — API endpoint contract tests
- Phase 4 — minimal read-only API
- Phase 5 — smoke script

## 12. Stop conditions

Stop if any of the following become required:

- graph DB is required
- Neo4j is introduced
- loader mutates snapshot
- loader calls live services
- traversal/blast-radius logic is added
- LLM reasoning is introduced
- remote snapshot URL is required
- existing graph projection behavior changes

Graph Snapshot Loader Design — docs-only, not implemented.
